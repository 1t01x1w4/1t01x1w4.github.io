XXE，即XML外部实体注入（XML External Entity），与其它注入类漏洞有异曲同工之妙。当 XML 解析器配置不当，允许解析外部实体时，攻击者可以通过构造恶意 XML 来读取服务器本地文件、探测内网端口、执行 SSRF，甚至在某些情况下实现远程代码执行。本文旨在梳理XEE漏洞利用的方法、流程以及绕过手法等。

确认 XEE 类型

XEE 按回显情况分三种，对应三种不同的利用策略：

回显情况 类型 策略
响应中直接出现文件内容 有回显 XXE 直接用&xxe;塞进回显字段，一步到位读文件
响应不出现，但目标能出网 OOB XXE 在自己的 VPS 上放外部 DTD，把数据带出来
响应不出现，目标不出网 盲 XXE Error-based，用file:///nonexistent/%file; 触发报错，从错误信息里提取数据

分步判断流程

  1. 提交一个正常 XML，观察响应中哪些字段会原样返回
  2. 插入一个内部实体引用&xxe;，确认解析器是否处理实体
  3. 把实体内容换成file:///etc/hostname，看回显字段是否出现文件内容
  4. 如果第 3 步无回显，在自己的 VPS 上起监听，尝试 OOB 外带
  5. 如果第 4 步收不到请求，切到 Error-based 模板

payload 构造模板

模板 A - 有回显

常用协议：

协议 用途 示例
file:/// 读取文本文件 file:///etc/passwd
php://filter/convert.base64-encode/resource= 读取 PHP 源码（必须 Base64 否则会被执行） php://filter/convert.base64-encode/resource=/var/www/html/config.php
http:// SSRF / 外带数据 http://vps-ip:8888/
expect:// 命令执行（需 PHP expect 扩展，罕见） expect://id

模板 B - OOB（Out-of-Band，外带数据）

用于没回显但靶机能出网时，核心思路是把文件内容拼到 HTTP 请求的 URL 参数里发到攻击机。

第一步：向目标提交带外部 DTD 引用的 XML

第二步：在 VPS 的 Web 根目录下放置evil.dtd

第三步：攻击机上起监听

目标解析 XML 后，攻击机会收到类似GET /?data=root:x:0:0:root...的请求，文件内容就在 URL 参数里。

模板 C — Error-based（基于报错）

如果既无回显也不出网，可以尝试把文件内容拼进一个不存在的文件路径，触发解析器报错，从错误信息里提取数据。

解析器会报类似Warning: failed to load external entity "file:///nonexistent/root:x:0:0:root..."的错误，文件内容就在报错里。

信息收集优先级

拿到 XEE 后可以按照以下优先级顺序，对信息逐级枚举，这个过程和 SQL 注入列举表名、字段名很像。

优先级 1：应用源码

如果不知道请求的是哪个文件，可以先读/etc/nginx/nginx.conf或/etc/apache2/sites-enabled/000-default.conf，看 Web 根目录配在哪。

优先级 2：用户家目录

优先级 3：系统配置

优先级 4：横向移动

  • 内网端口探测：用 SSRF 扫http://127.0.0.1:3306、http://127.0.0.1:6379等常见服务端口
  • 账密撞库：从源码/配置文件拿到的账密去试管理后台、数据库、SSH 等
  • SSH 私钥横移：读到id_rsa后，先用authorized_keys确认授权范围，然后ssh -i id_rsa user@target
  • 凭据复用：一套账密往往多个服务共用，不要只试一个地方

常见问题与绕过技巧

读 PHP 源码

file://直接读.php文件会被 PHP 引擎解析执行，返回的是空白或执行结果，不是源码。必须用php://filter套一层 Base64：

WAF 绕过

限制 绕过方法
SYSTEM关键字被黑名单拦截 utf-7 编码、大小写混合SyStEm、改用参数实体
file://协议被过滤 换php://filter/、gopher://、或用 SSRF http://127.0.0.1/间接读
目标不出网 Error-based 模板，走报错通道
云主机/容器没有/etc/passwd 读/proc/self/cwd获取当前工作目录，或读 /proc/self/mounts了解文件系统
防火墙封了 80 出站 OOB 改用 53(DNS)、443(HTTPS)、8080 等常见出站端口
CDN/WAF 环境 VPS 收不到 HTTP 请求 改用 DNS 外带——把文件内容编码成 DNS 查询的子域名

XML 参数实体 vs 普通实体

可能会有一个疑问：为什么 OOB 模板里用的是%xxe;而不是&xxe;？

类型 声明 调用 可用位置
普通实体 <!ENTITY name "value"> &name; XML 文档内容
参数实体 <!ENTITY % name "value"> %name; 仅 DTD 内部

参数实体只能在 DTD 内部使用，OOB 和 Error-based 模板里嵌套实体引用必须用参数实体，这也是绕过某些 WAF 规则的关键。
