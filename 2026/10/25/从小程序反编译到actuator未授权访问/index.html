漏洞简述

Web 服务端未对 Spring Boot 运维监控接口做身份认证与访问控制，攻击者无需登录即可直接访问运维管理端点，读取应用的环境配置、接口路由、配置项和 Bean 结构等运行信息，并且内存转储文件能够被完整下载。内存转储文件一旦被获取，其中的会话凭证、用户手机号与姓名等个人信息、数据库口令以及第三方密钥将直接泄露。

危害

该漏洞本质是未授权访问导致的信息泄露，但泄露的内容恰好是系统最核心的凭据与业务数据，属于「单点入口、全链失守」型风险，综合评定为高危。具体危害可沿攻击链展开：

  1. 核心凭据泄露，可直接接管数据资产。 heapdump 是 JVM 运行时的完整内存快照，spring.datasource 的账号口令、Redis 连接串、第三方 SDK 的 accessKey/secretKey 在内存中均以明文形式存在，用 JDumpSpider、MAT 或 strings 即可批量提取。攻击者据此可直接连接数据库与缓存，读取、篡改、删除订单和用户数据；若 Redis 侧未做鉴权或存在弱口令，还能进一步通过写入计划任务、主从复制投毒等方式获取服务器权限，使风险从数据泄露升级为服务器失陷。
  2. 个人信息大规模泄露，触发合规责任。 内存中持有大量运行态数据：用户会话 Token、手机号、姓名、收货地址、购票与支付记录等。攻击者可批量导出后用于精准诈骗、撞库、账号盗用，属于《个人信息保护法》《数据安全法》明确要求上报的情形，同时难以满足等保对敏感数据访问控制的要求。
  3. 业务与资金安全受威胁。 该应用涉及微信小程序与支付回调，env 与 heapdump 中很可能包含微信 appsecret、支付商户密钥、短信服务密钥、对象存储 AK/SK。攻击者可伪造支付结果通知实现 0 元购、调用短信接口实施短信轰炸并消耗账户余额、伪造小程序登录态接管账号，或直接拖取对象存储中的票券、证件等文件。
  4. 暴露内部攻击面，为后续渗透提供跳板。 mappings 与 beans 给出全部接口路由和类结构，configprops、env 泄露内网地址、中间件版本与外部依赖配置，攻击者无需再盲扫即可定位未公开接口、后台管理地址与内网资产；health 返回 UP 则便于攻击者做资产测绘与批量筛选。这些信息显著降低后续利用成本。
  5. 攻击隐蔽，事后难以追溯。 actuator 探测请求体量极小，仅 HEAD 请求就能确认 heapdump 可下载，常规 WAF 规则通常不会拦截，访问日志里表现为普通 GET，难以区分正常监控流量与恶意拉取。若未及时审计网关、Nginx 日志，可能在很长时间内都无法发现凭据已被取走。

修复建议

  1. 在网关/WAF 封禁 /actuator/* 与 /frontUIWebapp/actuator/*，返回 404。
  2. 关闭非必要端点，尤其是 heapdump、env、configprops、beans、mappings。
  3. 将 management 端口与业务端口分离，仅允许运维网段访问。
  4. 视为凭据已泄露：轮换数据库、Redis、微信、支付、短信、对象存储等密钥。
  5. 使旧会话 Token 失效，必要时强制用户重新登录。
  6. 审计网关、Nginx、WAF 访问日志，确认是否已有外部 IP 访问 heapdump 或 env。

如需保留监控能力，应将 management 绑定到独立端口并限制来源：

  • 未授权访问
